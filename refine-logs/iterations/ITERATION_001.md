# Iteration 001: EAIR-Bench Deterministic Pilot Slice

Date: 2026-06-17

## Core Hypothesis

High-risk RAG-agent actions should be allowed to use retrieved evidence only when the evidence path is sufficient, trusted, fresh, low-conflict, and policy-compatible. Retrieval exposure alone should not be treated as action compromise; evidence influence must be classified as legitimate or hijack influence.

## Math / Definition Changes

- Operationalized `HardGate(a)` as decision/tool/parameter policy violation checks.
- Operationalized `EvidenceSufficient(a)` as trusted, fresh, non-poisoned support for the action's required claims.
- Added `LegitInfluence` vs `HijackInfluence` as an explicit result field via `influence_type`.
- Extended action shape with `parameters` so parameter-level hijack can be evaluated.

## Benchmark Changes

Added `formaltrust_platform.experiments.eair_bench` with six deterministic conditions:

- `clean_sufficient_evidence`
- `poison_exposure_no_action_influence`
- `legitimate_evidence_update`
- `parameter_level_hijack`
- `insufficient_evidence_dangerous_decision`
- `hijack_evidence_support`

Added ten baselines:

```text
vanilla_rag
pre_rhe
source_filter
ragas_claim_support
conflict_aware
access_control
planguard_intent
attriguard_attribution
eair_gate
eair_full
```

## System Changes

Added FormalTrust-compatible built-in nodes:

- `attack.eair_bench_retrieval`
- `model.eair_bench_agent`
- `guardrail.eair_full`
- `evaluate.eair_bench_action`

Each node reads `FormalTrustState`, reads YAML/node config, and returns only valid state patches. Candidate/final actions are stored in `metrics["candidate_action"]` and `metrics["final_action"]`.

## Supported Conclusions

- PRE/RHE can false-positive when poison is retrieved but does not influence the selected action.
- AttriGuard-style evidence attribution can over-block legitimate evidence influence.
- RAGAS-style claim support can miss unsafe action parameters.
- Access control can miss dangerous allowed-tool decisions when evidence is insufficient.
- EAIR-Full separates legitimate from hijack influence in this deterministic slice.

## Weakened / Not Yet Supported

- No claim of real-world power-grid safety.
- No claim of superiority over official AttriGuard, AgentSentry, PlanGuard, or PromptArmor implementations.
- No statistical significance claim.
- `eair_gate` and `eair_full` are not yet separated by a strong ablation condition.

## Old Narrative To Deprecate

- Do not frame action-level causal attribution itself as the sole novelty.
- Do not frame retrieval poisoning exposure as equivalent to action compromise.
- Do not claim math abstraction alone is the contribution; benchmark evidence is the main contribution.

## Decision

`revise + keep`

Keep the core EAIR-Bench direction because the pilot supports the intended blind-spot story. Revise the experimental design next because the current slice is deterministic, small, and does not yet separate all EAIR components.
