# Iteration 092: Automate Protected-Field Claim Promotion

## Goal

Remove the manual JSON-path step between the reportable protected-field table and paper-ready claims. If protected action fields are the paper's main object, their claims must be generated by the same reproducible claim-template path used by the live runbook.

## Updated One-Sentence Thesis

High-risk RAG-agent actions should execute only when every protected action field carries a reviewed, hash-pinned evidence warrant claim proving sufficient, fresh/current, source-diverse, low-conflict support.

## Current Strongest Contributions

1. **EAIR-Bench.** Benchmark contribution: evidence-to-action admissibility over protected action fields, with field-level reportable rows.
2. **Evidence Warrant / Proof-Carrying Action.** Representation contribution: `(a, W_a)` binds action fields to replayable support obligations and paper-citable JSON paths.
3. **WarrantGuard / EAIR-Gate.** System contribution: verifies hard action obligations and warrant sufficiency, then emits reportable field-level claims for review and sealing.

## What Changed

- `eair-write-reportable-claim-template` now emits `protected_field_warrant_quality_*` claims for every `protected_field_rows.*.warrant_quality_score` entry.
- Added a focused regression test proving the generated protected-field claim is auditable by `eair-audit-reportable-claims`.
- Upgraded the fixture `reportable_claims.json` from 4 claims to 6 author-prepared claims.
- Regenerated claim audit, paper-ready review declaration, strict paper-ready audit, reviewed claim bundle seal, and seal verification.
- Ran live matrix preflight/status; the current live provider workflow is blocked because `OPENAI_API_KEY` is not set.

## Novelty Pressure Test

| Neighbor | Solves | Remaining difference |
|---|---|---|
| AttriGuard / CausalArmor | Attribute or bound untrusted influence over actions/tool calls. | The generated claim object is field-level warrant validity, not influence attribution alone. |
| PlanGuard / PromptArmor | Check plan consistency, constraints, and prompt-injection effects. | The promoted claim asks whether `decision`, `risk_report`, or `tool` has sufficient evidence support after protocol adherence. |
| AIRGuard / Agent-Sentry / AgentSentry | Enforce authority, provenance, or runtime execution boundaries. | The claim chain can cite evidence-insufficient failures for allowed or no-tool actions. |
| RAGForensics / RAGChecker / ARES | Trace RAG sources or evaluate answer/context faithfulness. | The claim path targets action-field warrant quality, not answer-level faithfulness. |
