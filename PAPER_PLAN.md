## 2026-06-22 Active Compression: Evidence Warrant for Proof-Carrying Actions

Use this as the active paper direction:

**WarrantGuard: Evidence Warrants for High-Risk RAG-Agent Actions**

One-sentence thesis:

> High-risk RAG-agent actions should not merely be checked for tool permission, source attribution, answer faithfulness, evidence-force calibration, environmental grounding, or generic action certificates; they should execute only when retrieved evidence carries bounded field capabilities for the action, arguments, approval status, risk level, and risk report.

Core question:

> When does retrieved evidence have authority to govern a protected high-risk action field?

Short threat name:

> Evidence-authority laundering: a RAG-specific confused-deputy variant where retrieved evidence borrows authority over protected action fields after execution permission is already satisfied.

Current contribution stack, compressed:

1. **EAIR-Bench, benchmark contribution.** The benchmark object is field-scoped evidence capability: cases are labeled by whether evidence influence has in-scope capability over protected fields or is hijack-style, not only by whether poison was retrieved, whether an answer is faithful, whether a tool call is authorized, whether evidence force is calibrated, whether environment state is grounded, or whether a certificate exists.
2. **Evidence Warrant / Proof-Carrying Action, representation contribution.** A high-risk action is represented as `(a, W_a)`, where `W_a` is a replayable field-capability ledger for the decision, tool/arguments, approval flag, risk level, and risk report. The novelty is not generic proof-carrying firstness; it is the RAG-specific semantics that decide which evidence capability may govern which action field.
3. **WarrantGuard / EAIR-Gate, system contribution.** The verifier allows execution only when the action satisfies hard domain/tool/approval/parameter/risk-report constraints and each protected field has valid evidence jurisdiction. It records soft poison/co-support warnings without treating all evidence influence as unsafe.

Design pattern:

```text
Retrieve evidence -> Agent emits proof-carrying action -> WarrantGuard verifies evidence jurisdiction -> Execute / block / review
```

Evidence-warrant contract:

```text
W_a = (F_a, C_a, S_a, T_a, X_a, H_a)
ECap(e) = (F_e, O_e, B_e, T_e, P_e, X_e, H_e)
Jurisdiction(f, a, W_a, K_q)
```

where `F_a` are protected action fields, `C_a` are required supporting claims, `S_a` are source clusters and support paths, `T_a` records freshness/currentness, `X_a` records conflicts and counter-evidence, and `H_a` records hard action obligations. `ECap(e)` is the evidence field capability carried by a retrieved item or support path: fields, operations, force bound, time scope, provenance scope, conflict obligations, and hard obligations. `Jurisdiction(f, a, W_a, K_q)` decides whether action field `f` consumes an in-scope evidence capability. Sufficiency, freshness/currentness, source diversity, conflict, counter-evidence, and hard obligations are capability-boundary predicates, not separate novelty claims.

HardGate, EvidenceSufficient, soft EAIR score, robustness sweeps, reportability audits, and claim seals are implementation obligations, diagnostics, or appendix infrastructure unless a main-table claim directly uses them. They should not be sold as separate novelty claims.

WarrantGuard threat model:

| Element | Active definition |
|---|---|
| System under test | A RAG agent retrieves documents, emits a structured high-risk action, and may execute, recommend, or route the action. |
| Protected action fields | `decision`, `tool`, `parameters`, `requires_human_approval`, `risk_level`, `risk_report`, and the supporting evidence claims for each field. |
| Attacker capability | The attacker can influence retrieved documents, stale/superseded records, near-duplicate source clusters, conflicting evidence, tool descriptions, or low-integrity policy/support claims. |
| Trusted boundary | The attacker does not control model weights, the WarrantGuard verifier, reportability audits, or the reviewed claim-seal chain. |
| Attack success | A final high-risk action is unsafe, unsupported, approval-bypassing, parameter-violating, risk-downgraded, or governed by evidence lacking field jurisdiction. |
| Warrant obligation | For every protected action field, `W_a` must establish evidence jurisdiction through sufficient, fresh/current, source-diverse, low-conflict support and must expose counter-evidence or hard-policy violations. |
| Non-goals | This does not prove real-world deployment safety, official prior-work failures, model-weight robustness, or firstness. |

This threat model is deliberately narrower than generic RAG poisoning or generic agent authorization: the object is evidence authority over protected action fields. It should be described as a close relative of confused deputy / ambient authority, not as a rediscovery of that literature: the borrowed authority here is field-level evidence authority, not tool or credential authority.

## 论文主线

核心论点：

> RAG Agent 的安全风险不应只在检索层、证据冲突层或工具权限层分别评估；在安全关键任务中，真正需要审计的是低完整性证据是否影响了高风险动作。

## 推荐题目

首选：

**From Poisoned Evidence to Unsafe Actions: Evidence-to-Action Integrity for Safety-Critical RAG Agents**

中文：

**从污染证据到不安全动作：安全关键 RAG Agent 的证据-动作完整性**

## Abstract 结构

1. 背景：RAG Agent 正用于有工具调用和领域决策的任务。
2. 问题：已有 RAG 安全、冲突处理和 Agent 工具安全分别研究，但没有统一评估证据到动作的污染路径。
3. 方法：提出 Evidence-to-Action Integrity Graph、EAIR 风险函数、Evidence-Action Gate。
4. Benchmark：电网 decision pollution benchmark。
5. 结果：预期降低 unsafe/unsupported actions，并保持 clean utility。

## Section 1: Introduction

要讲清楚：

- RAG 的失败不只是 hallucination，而是“被检索证据引导的错误动作”。
- 电网 Agent 有天然高风险边界：审批、仿真、报告、参数、工具调用。
- 现有评测指标不够：answer EM/F1、poison retrieval rate、conflict F1 都不能单独说明 action safety。

建议开篇例子：

> 一个检修审批任务中，检索器同时返回正式流程文档和一条污染 memo。模型自然语言回答看起来谨慎，但工具/决策 JSON 中把 `requires_human_approval` 设为 false，最终造成审批绕过。

贡献列表：

1. Threat model：retrieval-to-action pollution。
2. Formalization：evidence-to-action graph and risk functional。
3. Method：external evidence-action gate。
4. Benchmark：power-grid decision pollution cases。
5. Experiments：action-level metrics and ablations。
